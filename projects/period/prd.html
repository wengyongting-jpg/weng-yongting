Period — AI-Assisted Personalized Health Application

Author: Yongting Weng (Designer)  ·  Status: Live demo at period-ai.vercel.app  ·  Version 1.0

01 · PROBLEM

A generic chatbot cannot be trusted with health-adjacent reasoning

  • Fragmented health information — cycle, symptoms, mood, and medication records live in different places, so no single view of the user's state exists.
  • Generic health info — template answers do not reflect an individual's cycle phase or personal context.
  • AI overstating certainty — in health-adjacent products, a confident wrong answer is a safety risk, not a UX bug.
  • Personal data sensitivity — health records require structured data models and deliberate handling.

02 · TARGET USERS & SCENARIOS

Primary user: women who track their menstrual cycle and want personalized, context-aware daily health support rather than generic articles.

Core scenario: a user logs today's symptoms and mood, then asks "why do I feel exhausted today?" — the answer must reflect her recorded cycle phase and history, and must stay inside safe, non-diagnostic boundaries.

03 · PRODUCT DESIGN — HYBRID AI ARCHITECTURE

Split reasoning: deterministic logic where accuracy matters, LLM where personalization matters

The key design decision: the architecture — not the prompt — is what makes an LLM safe to ship in health-adjacent products.

04 · FUNCTIONAL REQUIREMENTS

  • P0 — Record cycle, symptoms, mood, and medication with structured fields.
  • P0 — Personalized daily insight grounded in the user's recorded cycle phase.
  • P0 — Conversational support with explicit safety boundaries (no diagnosis, no medication advice).
  • P1 — Trend view across cycles (symptom / mood patterns).
  • P1 — Context injection so every LLM response references the user's actual data.

05 · SUCCESS CRITERIA & VALIDATION

North Star: daily active logging rate — the product only works if users record consistently enough for personalization to be meaningful.

Safety metric: zero out-of-boundary responses (diagnosis / medication advice) in scripted safety test cases.

Current status: live demo at period-ai.vercel.app. User-interview evidence and measured funnel metrics are not yet collected — the next iteration starts there.

06 · ITERATION PLAN

  • Now — run 5–8 user interviews to validate the pain-point assumptions behind the feature set.
  • Next — instrument logging funnel (open → record → insight viewed) to find the drop-off point.
  • Later — expand the safety test suite and add regression checks before any prompt change ships.
